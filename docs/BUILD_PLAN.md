# BUILD_PLAN — WorthIt.gg (compressed / ASAP)

**Shape:** build compresses to ~48 hours with Claude Code; users don't. Launch
Day 3, then a low-intensity 5–6 day tail (1–2 hrs/day) for users, interviews,
and ONE evidence-driven iteration. Total ~8–9 days.

**Rule of the plan:** one commit per sub-phase, message prefixed with its
number (`1.2: content filter layer`). Plan mode before every non-trivial step.
Every "DoD" (definition of done) is checked by the developer, not assumed.

---

## Phase 0 — Setup (done manually, ~2 hrs)

- 0.1 Rotate Gemini key → `.env`. PostHog account + key. GitHub repo (public).
  Vercel account linked.
- 0.2 Scaffold = this repo layout. **First commit is `.gitignore` alone.**
- 0.3 `CLAUDE.md` reviewed and committed.
- 0.4 `pipeline/fetch_reviews.py` in place.
- **DoD:** repo pushed; `.env` present locally and absent from git;
  `git log` shows .gitignore-first history.

## Phase 1 — Pipeline (~4 hrs, one session)

- 1.1 **Ingestion hardening** of `fetch_reviews.py` (do not rewrite): per-bucket
  quotas; merge `filter=recent` + `filter=all` deduped on `recommendationid`;
  skip-if-cached; exponential backoff on 429. Run on all 5 seed games.
  **DoD:** bucket distribution printed per game and eyeballed by developer;
  refund cohort > 0 for every title (else fix sampling before proceeding).
- 1.2 **Content filter layer** (BEFORE extraction): ♥-density threshold;
  `votes_funny > votes_up` exclusion; LDNOOBW wordlist; length/low-info
  heuristic. Prints what it filtered.
  **DoD:** developer has read ~20 filtered-out reviews and tuned thresholds.
- 1.3 **Extraction pass** (Gemini Flash-Lite, temp 0, structured output): per
  bucket → claims with supporting IDs; ≥2-review rule enforced in code.
  **DoD:** one game's raw extraction output read by developer before 1.4.
- 1.4 **Deterministic grounding check** (no LLM): cited IDs exist; lexical
  overlap between claim and cited text; **prevalence-language guard on claim
  prose** (`pipeline/prevalence_guard.py`, built in 1.2 — a countless schema
  cannot catch "most players bounce off the tutorial"); reject + regenerate on
  failure.
  **DoD:** deliberately corrupted claim gets rejected in a test, and a claim
  carrying prevalence language is rejected with its offending term named.
- 1.5 **Synthesis pass** (Gemini Flash): verdict JSON from extracted claims
  only; unknown claim IDs rejected in code. Output schema: verdict,
  for-whom, per-bucket sections, claims+citations, distortion flags.
  **DoD:** all 5 seed verdicts generated end-to-end and read in full by
  developer. This is the go/no-go moment for the product thesis.

## Phase 2 — Evals (~3 hrs) — rubric and spot-check are NOT delegated

- 2.1 Generate ~50 candidate test cases from seed games (claim + cited IDs).
- 2.2 **Developer writes rubric wording** for QR-1..QR-4 (interview material).
- 2.3 Build LLM-as-judge runner.
- 2.4 **Developer hand-scores 10 cases**; reconcile with judge before trusting it.
- 2.5 Baseline run → `evals/RESULTS.md` (dated, append-only).
- 2.6 QR-4 gate wired into the batch script: any safety failure blocks output.
- **DoD:** RESULTS.md has a dated baseline row for QR-1..4.

## Phase 3 — Site (~3 hrs) — follow docs/DESIGN.md exactly

- 3.1 Next.js static site from `public/verdicts/*.json`: home (search + grid),
  verdict page (citations collapsed by default).
- 3.2 Methodology page: segmentation logic, live eval scores, sample-vs-Steam
  distribution, Death Stranding side-by-side (Steam summary vs WorthIt).
- 3.3 PostHog events: session, search, verdict_view, citation_expand,
  request_submit. **DoD includes events verified firing in the PostHog UI.**
- 3.4 Request-a-game input (title only) → PostHog event.
- 3.5 Mobile pass (most Reddit traffic is mobile) + keyboard focus visible +
  reduced-motion respected.
- **DoD:** unlisted Vercel deploy renders all 5 seed verdicts correctly on a
  phone.

## Phase 4 — Catalog + quota (overnight)

- 4.1 Assemble ~100–150 appids (top sellers / most reviewed). 100 is enough —
  catalog size never delays launch.
- 4.2 Quota plan: self-consistency double-run on seed games only; single-pass
  long tail; split across two nights if needed (~1,500 req/day ceiling).
- 4.3 Overnight batch with backoff; commit generated JSONs.
- 4.4 Morning audit: 10 random verdicts spot-checked; **20 random citations
  manually audited for QR-4.** Last gate before strangers.
- **DoD:** audit notes appended to evals/RESULTS.md; QR-4 clean.

## Phase 5 — Launch (Day 3)

- 5.1 Morning: warm channels (campus gaming groups, Discords, IIIT-D friends).
- 5.2 Fix breakage (Claude Code loop).
- 5.3 Afternoon: 5–8 genuine-answer replies on r/ShouldIBuyThisGame, link at
  bottom.
- 5.4 Per-game verdict posts in r/Kenshi, r/DeathStranding, r/cyberpunkgame etc.
- 5.5 Book 8 interview slots for Days 4–6.
- **DoD:** at least one verdict generated by someone the developer doesn't know.

## Phase 6 — Tail (Days 4–8, 1–2 hrs/day) — FEATURE FREEZE

- 6.1 5 Reddit replies/day; interviews 1–6 (watch them use it, log hesitations
  verbatim).
- 6.2 All feature impulses → BACKLOG.md. No exceptions. This is where Claude
  Code's cheapness becomes the risk.
- 6.3 Day 7: analysis, no code. Funnel + interview themes + request log → the
  one dominant failure. **Developer writes hypothesis + success metric BEFORE
  any change** (the decision doc — most interview-valuable artifact).
- 6.4 Day 8: ship that one iteration; re-run evals → before/after delta;
  regenerate affected verdicts.
- **DoD:** decision doc exists; RESULTS.md has a post-iteration row.

## Phase 7 — Package (Day 9, ~3 hrs)
